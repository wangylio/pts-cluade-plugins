# 数据库设计说明书 (lld-database)

## 用途

撰写**数据库设计说明书**，把业务对象与数据需求细化到可建库的粒度：实体关系、表结构、字段、索引、数据字典、建表语句与初始化语句。

- 有 HLD 时从数据模型概要推导；没有 HLD 时，从 PRD、现有系统、代码或使用者口述取证。
- 只写数据库设计，不写接口报文、模块内部实现、部署与运维。
- 只输出 markdown；需要 Word 时由使用者调用 `md2docx` 转换。

## 触发条件

- 要求「写数据库设计」「写表结构设计」「写数据字典」「写数据库设计说明书」，或输入 `/lld-database` 时使用。
- 只需要接口字段或模块内部实现时，不使用本技能。

## 输入来源

按优先级取证，高优先级覆盖低优先级：

1. 对话中提供的需求、业务对象、数据规则与约束。
2. HLD（如有）、PRD、现有系统设计文档。
3. 现有代码、DDL、ORM 模型、历史数据字典、数据量统计。
4. 使用者口述与 DBA 规范。

规则：

- HLD 不是必需输入；没有 HLD 时不要求使用者先补。
- 不要求输入文件位于固定路径；读不到即降级取证，不按文件名或常识臆测内容。
- 信息不足时按现有材料取最合理方案成文，不中断；未定项在交付对话中列出。
- 现有代码与材料冲突时，以使用者确认的需求和设计为准，代码只作参考。

## 工作流

1. 确认项目/特性名称、输出目录、覆盖范围，以及数据库类型与版本。
2. 提炼实体清单，建立实体与表的对应关系；材料不足时直接按最合理方案划分。
3. 确定命名规范与字段公共约定后开始成文。
4. 按「章节骨架」逐表展开：每张表一次写全六节，再写下一张表。
5. 自检后在对话中交付待确认项、设计缺口与建议补充材料，并告知文件路径。

目标文件已存在时，先询问覆盖还是改名。

## 章节骨架

`<...>` 按实际项目替换，`——` 后为该节内容。固定章节不得删减；无对应内容时删除该节并顺延编号，不留空节。

```
1. 文档概述
   1.1 编写目的
   1.2 设计范围 —— 覆盖的数据库、模式、业务对象与表；明确不包含的部分
   1.3 读者对象 —— 表格：读者角色、关注内容
   1.4 术语与缩略语 —— 表格：术语/缩略语、含义、说明
   1.5 命名约定 —— 表名、字段名、索引名的命名规则与示例

2. 数据库说明
   2.1 数据库类型与版本
   2.2 数据库特性说明 —— 本设计依赖的特性及使用范围，如分区表、JSON 字段、序列、存储引擎、事务隔离级别

3. 实体关系设计
   3.1 实体清单 —— 表格：实体名称、说明、所属业务对象、对应表名
   3.2 实体关系 —— 表格：起始实体、目标实体、关系类型、基数、说明

4. 表结构设计
   4.1 表清单 —— 表格：表名、中文名、表类型（主表/明细/字典/日志/关联）、所属业务对象、说明
   4.2 <表一>
       4.2.1 表说明 —— 表用途、数据量预估
       4.2.2 字段定义 —— 表格：字段名、类型与长度、必填、默认值、含义、取值范围、约束
       4.2.3 索引与约束 —— 表格：索引名、索引类型、字段顺序、唯一性、用途
       4.2.4 数据字典 —— 本表使用的枚举/码表：字段名、取值、含义、是否可扩展；无则写「无」
       4.2.5 建表语句 —— sql 代码块
       4.2.6 数据初始化语句 —— sql 代码块；无则写「无」
   4.3 <表二> —— 结构同 4.2
   4.N <表 N> —— 结构同 4.2

5. 文档修订记录 —— 表格：版本、日期、修订内容、修订人，位于正文最后
```

结构要求：

- 全文层级不超过四级；不设对象编号，表、实体、枚举统一以名称引用。
- 一张表写完再写下一张，同一张表的内容不得拆到不同章节。
- 每张表的六节必须齐全，不得合并；无内容时写「无」，不删小节。
- 字段表写全：主键、外键、唯一性写在「约束」列。
- 建表语句必须与字段表、索引表逐项一致，包含主键、外键、唯一约束与索引。
- 初始化语句用于字典、码表或默认数据，应可重复执行或写明执行前提。
- 修订记录固定放在正文最后，每次修订追加一行。

## 写作规范

- 字段类型用目标数据库的写法（如 `varchar(64)`、`numeric(18,2)`），不使用「字符串」「数字」这类模糊表述。
- 表名、字段名全文统一，同一含义使用同一名称。
- 文档自成体系，不要求读者查阅其他文档；不写「见某文档第 X 节」一类引用。
- 不写接口报文、模块内部的类与流程、部署运维、测试数据。
- 表格与列表不嵌套；不使用 mermaid。
- 文件为 UTF-8 编码，无 BOM。

## 输出

输出路径由使用者指定。文件顶部必须包含：

```yaml
---
title: <项目或特性名称> 数据库设计说明书
doc-type: LLD
doc-part: DB
version: V1.0
author: <作者>
date: <YYYY-MM-DD>
confidentiality: 内部
cover: true
toc: true
---
```

`doc-part` 固定为 `DB`；`author` 取使用者指定的人或需求文档的修订人；`date` 取成文当天；首版 `version` 为 V1.0。无法确定时留空，并在交付对话中说明。

## 交付说明（仅对话输出，不写入文档）

- **待确认清单**：未能确定、按假设写入的事项，每条写明当前假设、依据、影响范围与需确认人。
- **设计缺口**：材料未覆盖但建库必须确定的问题，说明影响哪一章节。
- **建议补充材料**：现有 DDL、数据量统计或 DBA 规范；没有时必须说明。

## 自检清单

- frontmatter 齐全；1~5 章齐全；每张表的六节齐全。
- 每个字段的类型、长度、必填、默认值、含义、取值范围、约束完整。
- 每张表的主键、外键与唯一约束明确；每个索引写明字段顺序与用途。
- 数据字典完整；建表语句与字段表、索引表一致；初始化语句可执行。
- 一张表的内容集中在一处，未被拆分。
- 无跨文档引用，无接口、模块实现、部署与运维内容。
- 表格与列表不嵌套；SQL 均标注 `sql`；文件为 UTF-8 无 BOM。
