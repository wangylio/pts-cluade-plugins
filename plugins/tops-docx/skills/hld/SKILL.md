# 概要设计文档 (hld)

## 用途

推导并撰写**高层设计文档 / 概要设计文档**，描述系统总体架构、模块划分、模块间交互、数据与接口的概要设计，输出为 UTF-8 编码的 markdown 文件。

本技能只负责「写成 markdown」。需要 Word 文档时，由使用者再调用 `md2docx` 技能按 docx 模板转换。

## 触发条件

- 使用者要求「写概要设计」「写高层设计」「写 HLD」时使用。
- 使用者提供 PRD 内容并要求据此产出设计文档时使用。
- 使用者说 `/hld` 时使用。

## 输入来源

内容**由 PRD 推导**。PRD 内容的获取方式（任选其一，优先使用者当前提供的形式）：

1. 使用者在对话中粘贴的 PRD 内容
2. 使用者指定路径的本地 PRD 文件
3. 使用者口述的需求要点

三种方式都拿不到时，先向使用者索取，不得凭空设计。**不要求 PRD 文件存在于固定路径**——本技能必须能脱离仓库中的 PRD 文件独立成文。

推导过程中缺少关键信息（如部署形态、外部系统、性能约束）时，向使用者提问确认。

## 工作流

1. 确认项目/特性名称与设计范围。
2. 取得 PRD 内容，提炼功能清单与非功能要求。
3. 按「章节骨架」逐章推导成文：
   - 模块划分对应 PRD 的功能分组，不要凭空增加功能
   - 每个模块写清职责边界与对外交互
   - 架构选择要给出理由
4. 自检：每条 PRD 功能在设计中有落点、模块之间无职责重叠、无跨文档引用。
5. 告知使用者将要写入的文件路径；目标文件已存在时先询问覆盖还是改名，确认后再写入。

## 输出

### 存放位置

```
docs/<项目或特性>/HLD-<名称>.md
```

### frontmatter

文件顶部必须包含以下字段（字段名固定，供 `md2docx` 识别封面信息）：

```yaml
---
title: <项目或特性名称> 概要设计文档
doc-type: HLD
version: V1.0
author: <作者>
date: <YYYY-MM-DD>
confidentiality: 内部
cover: true
toc: true
---
```

字段值未知时向使用者确认；确实无法确认时留空字符串，并在成文后列出待补充字段。

## 注意事项

- 设计内容必须能追溯到 PRD 中的功能或非功能要求，**不要设计 PRD 之外的功能**
- **不得引用其他文档**：不出现「见 PRD 第 X 节」「详见详细设计」一类跨文档引用，HLD 必须能单独分发
- 架构图、时序图用文字、表格或缩进文本表达，不要使用 mermaid
- 表格**不要嵌套**，列表**不要嵌套**——`md2docx` 的解析器只支持单层结构
- 文件必须为 UTF-8 编码
- 本技能不生成 docx；使用者需要 Word 版本时提示其调用 `md2docx` 技能
