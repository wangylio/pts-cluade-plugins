# 详细设计文档 (lld)

## 用途

推导并撰写**底层设计文档 / 详细设计文档**，把概要设计中的模块细化到函数、数据结构、接口字段、处理流程与异常处理，输出为 UTF-8 编码的 markdown 文件。

本技能只负责「写成 markdown」。需要 Word 文档时，由使用者再调用 `md2docx` 技能按 docx 模板转换。

## 触发条件

- 使用者要求「写详细设计」「写底层设计」「写 LLD」时使用。
- 使用者提供 HLD 内容并要求据此细化设计时使用。
- 使用者说 `/lld` 时使用。

## 输入来源

内容**由 HLD 推导**。HLD 内容的获取方式（任选其一，优先使用者当前提供的形式）：

1. 使用者在对话中粘贴的 HLD 内容
2. 使用者指定路径的本地 HLD 文件
3. 使用者口述的模块划分与架构要点

三种方式都拿不到时，先向使用者索取，不得凭空设计。**不要求 HLD 文件存在于固定路径**——本技能必须能脱离仓库中的 HLD 文件独立成文。

若使用者提供了代码库，可读取代码确认现有实现细节，但设计内容仍以 HLD 的模块划分为准。

## 工作流

1. 确认项目/特性名称与要展开的模块范围。
2. 取得 HLD 内容，提炼模块清单、接口与数据概要。
3. 按「章节骨架」逐章细化：
   - 每个模块写清职责、关键函数/方法、处理流程、异常处理
   - 接口写到字段级：名称、类型、含义、取值范围、错误码
   - 流程用编号步骤或缩进文字表达
4. 自检：HLD 中的每个模块都被展开、接口字段完整、异常路径有处理、无跨文档引用。
5. 告知使用者将要写入的文件路径；目标文件已存在时先询问覆盖还是改名，确认后再写入。

## 输出

### 存放位置

```
docs/<项目或特性>/LLD-<名称>.md
```

### frontmatter

文件顶部必须包含以下字段（字段名固定，供 `md2docx` 识别封面信息）：

```yaml
---
title: <项目或特性名称> 详细设计文档
doc-type: LLD
version: V1.0
author: <作者>
date: <YYYY-MM-DD>
confidentiality: 内部
cover: true
toc: true
---
```

字段值未知时向使用者确认；确实无法确认时留空字符串，并在成文后列出待补充字段。

## 注意事项

- 设计内容必须能追溯到 HLD 中的模块与接口，**不要引入 HLD 之外的新模块**
- **不得引用其他文档**：不出现「见 HLD 第 X 节」「详见需求文档」一类跨文档引用，LLD 必须能单独分发
- 时序图、状态图用编号步骤、表格或缩进文本表达，不要使用 mermaid
- 表格**不要嵌套**，列表**不要嵌套**——`md2docx` 的解析器只支持单层结构
- 代码片段放在围栏代码块中，标注语言
- 文件必须为 UTF-8 编码
- 本技能不生成 docx；使用者需要 Word 版本时提示其调用 `md2docx` 技能
