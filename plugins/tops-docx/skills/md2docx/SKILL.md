# Markdown 转公司标准 Word 文档（md2docx）

## 概述

读取一份 markdown，以技能自带的 `assets/template.docx` 为底稿，生成符合青岛鼎信 Q/DX 技术文档标准的 Word 文档。转换只做三件事：

1. **封面填空**：用 frontmatter 替换文档名称、发布日期、保密等级，其余封面元素保持底稿原样。
2. **目次重建**：删除底稿 TOC 缓存条目并重建域，页码交由 Word 更新。
3. **正文替换**：先读取正文样例中的列表缩进与表格列宽，再删除样例内容，写入 markdown 渲染结果，末尾追加标准「变更记录」表。

底稿同时提供骨架与样式；脚本以底稿为母版加载后另存为新文件，**底稿本身不会被修改**。

## 前置条件

| 依赖 | 检查方式 | 缺失时的处理 |
|------|----------|--------------|
| Python 3.x | `python --version` | 提示使用者安装 Python |
| python-docx | `python -c "import docx; print(docx.__version__)"` | 提示执行 `pip install python-docx` 后停止，**不要自动安装** |
| Word（可选） | 仅用于更新目录页码 | 跳过域更新，转换照常完成，提示使用者手动更新 |

## 调用方式

脚本位于本技能的 `scripts/md2docx.py`，用绝对路径调用：

```bash
python "<skill目录>/scripts/md2docx.py" --input "<markdown文件>" [--output "<输出docx>"]
```

示例（Windows / Git Bash）：

```bash
python "E:/Github/pts-cluade-plugins/plugins/tops-docx/skills/md2docx/scripts/md2docx.py" \
  --input "docs/电能表参数透传/PRD-电能表参数透传.md" \
  --output "docs/电能表参数透传/PRD-电能表参数透传.docx"
```

### 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `--input` / `-i` | 是 | 输入 markdown 文件（推荐 UTF-8） |
| `--output` / `-o` | 否 | 输出路径，默认与 markdown 同目录同名 `.docx` |
| `--template` / `-t` | 否 | 自定义底稿，默认使用 `assets/template.docx`；底稿必须满足「底稿与模板契约」 |
| `--check-template` | 否 | 只校验底稿契约并输出逐项结果，不生成文档（此时无需 `--input`） |
| `--h1-pagebreak` | 否 | 每个一级标题前自动分页（默认关闭；变更记录固定另起一页） |
| `--skip-com` | 否 | 不调用 Word 更新目录域 |
| `--version` | 否 | 显示脚本版本 |

指定 `--output` 且目标文件已存在时，先向使用者确认是否覆盖。

## 底稿与模板契约

默认底稿：`plugins/tops-docx/skills/md2docx/assets/template.docx`。脚本在转换前逐项校验以下结构与样式，**不满足契约直接报错退出**，不会降级拼装。

### 三区结构

底稿按分节符定位，三区缺一不可：

| 区域 | 内容 | 转换时的处理 |
|------|------|--------------|
| 第 1 节 | 封面（保密等级、Q/DX、标准号、文档名称、发布/实施日期、发布部门） | 保留，替换文档名称 / 发布日期 / 保密等级 |
| 第 2 节 | 目次页（「目　次」标题 + TOC 域，罗马页码） | 保留，清空缓存条目并重建 TOC 域 |
| 第 3 节 | 正文样例（「有序列表样式」示例、带序号列的样例表、末尾「变更记录」标准表，阿拉伯页码） | 读取样例的列表缩进与表格列宽，删除样例内容，写入 markdown 渲染结果与变更记录 |

### 必需样式

| 用途 | 样式名 |
|------|--------|
| 正文 | `段` |
| 一级标题 | `Heading 1` |
| 二级~六级标题 | `一级条标题`、`二级条标题`、`三级条标题`、`四级条标题`、`五级条标题` |
| 无序列表 1/2/3 层 | `列项——（一级）`、`列项●（二级）`、`列项◆（三级）` |
| 有序列表 | `段` + 底稿「有序列表样式」样例的编号定义（`1)`，样例段缩进 840/420） |
| 表格 / 单元格文字 | `Table Grid` / `表格内文字` |
| 图片 / 图题 | `图片格式` / `Caption` |
| 封面 | `封面标准名称`、`其他发布日期`、`文献分类号` |
| 目次 | `目次、标准名称标题`、`toc 1` |
| 变更记录标题 | `章标题` |
| 引用（可选） | `注：（正文）` |

### 底稿维护规则

- 不要手工删除底稿的分节符、封面元素或 TOC 域，否则三区定位会失败。
- 正文节的「有序列表样式」样例段是有序列表缩进的来源，带「序号」表头的样例表是表格列宽的来源；调整缩进或列宽直接改样例，脚本每次转换都会重新读取。
- 封面标准号、实施日期、发布部门保持底稿原文；需要按项目填写时先改底稿再转换。
- 更换公司模板：替换 `assets/template.docx`，并同步更新本文档的契约表与脚本中的 `STYLE_CONTRACT`。自定义底稿用 `--template` 指定，用 `--check-template` 单独校验。

## markdown 输入规范

### frontmatter

文件顶部可带 YAML frontmatter（`tops-docx` 插件的四个文档技能默认会写入）：

```yaml
---
title: 电能表参数透传功能 产品需求文档
doc-type: PRD
version: V1.0
author: 张三
date: 2026-10-28
confidentiality: 内部
cover: true
toc: true
---
```

| 字段 | 作用 |
|------|------|
| `title` | 封面「文档名称」 |
| `date` | 封面发布日期，`2026-10-28` 写成 `2026 - 10 - 28发布` |
| `confidentiality`（或 `classification`） | 封面保密等级（如 内部 / 限制 / 公开） |

字段未提供时保留底稿占位（`文档名称`、`2026 - 10 - 28发布`、`限制`）。`doc-type`、`version`、`author`、`cover`、`toc` 不参与转换，可原样保留。

### 标题

| markdown | 输出 |
|----------|------|
| 文档开头唯一的 H1 | 文档标题，只上封面，不写入正文 |
| 其余标题 | 按 `#` 层数映射到一级~五级条标题：存在文档标题时从 H2 起算（H2 → 一级条标题），否则从 H1 起算 |
| 超过五级 | 降级为 `五级条标题` 并告警 |
| 手工编号（`1.`、`1.1`、`一、`、`第X章`） | 自动剥离，编号由底稿标题样式生成，避免出现 `1 1. 概述` |
| 标题为 `目录` / `目次` 的章节 | 整章跳过，目录由底稿目次页提供 |

### 正文语法

| markdown | 输出 |
|----------|------|
| 普通段落 | `段`；段内软换行自动拼接，中文之间不插空格 |
| `-` / `*` / `+`（最多 3 层） | `列项——（一级）` / `列项●（二级）` / `列项◆（三级）` |
| `1.` / `1)`（支持嵌套） | `段` + 底稿编号定义，显示 `1)` `2)` `3)`；每个列表独立从 1 开始，首层沿用样例缩进，每嵌套一层增加 420 twips |
| GFM 管道表格 | `Table Grid` + `表格内文字`；表头加粗、灰底、跨页重复；`:---:` 控制列对齐；列宽见「表格列宽」 |
| ```` ``` ```` 代码块 | 逐行套 `表格内文字`，字体 Consolas |
| `>` | `注：（正文）`，缺少「注」前缀时自动补「注：」 |
| `---` | 水平线（**不是**分页符） |
| `\pagebreak` 或 `<!-- pagebreak -->` | 分页符 |
| `![图题](路径)` | 图片按版心宽度居中插入，图题用 `Caption`；路径相对 md 文件解析，缺失时写入占位说明并告警 |
| `**粗体**` / `*斜体*` / `` `行内代码` `` / `[文字](链接)` | 行内格式；链接只保留可读文字 |
| HTML 注释、反斜杠转义 | 注释丢弃，`\_` 等转义按字面输出 |

### 表格列宽

- 首列识别为序号列时（表头为 `序号` / `序` / `编号` / `No` / `#`，或表头为空且整列都是数字），列头统一写成「序号」，列宽取底稿样例表的序号列；其余列的表头保持 markdown 原文，不会替换成「列1」「列2」。
- 其余列按表头与单元格内容的显示长度分配宽度，表格总宽取底稿样例表总宽（约 9571 twips，随底稿变化）。
- 需要整体调整列宽时，修改底稿中带「序号」表头的样例表即可。

### 变更记录

标题命中 `变更记录`、`修订记录`、`文档修订记录`、`修订历史`、`变更历史` 时：

- 该章节首个表格的数据行灌入底稿末尾的标准表（版本 / 变更日期 / 变更说明 / 记录人）。
- 表头按语义映射：`日期` / `修订日期` / `修改日期` → 变更日期，`修订人` / `作者` / `修改人` → 记录人，`修订内容` / `说明` / `描述` / `内容` → 变更说明，`版次` → 版本；识别不出时按列序兜底并告警。
- 章节内表格之外的内容忽略并告警；markdown 没有该章节时保留一张只有表头的空表。
- 该章节固定置于全文末尾并另起一页，其余章节连续排版。

### 不支持的语法

- mermaid、PlantUML、Graphviz 等图形块无法离线渲染：原样保留为代码块并告警，请改用文字、表格或本地图片。
- 嵌套表格、脚注、公式、HTML 片段。

## 输出与验收

脚本结束会打印：

```
[完成] 已生成：<输出路径>
  底稿：<底稿路径>
  文档标题：已作为封面标题处理，不写入正文        # 存在文档标题时
  统计：标题 N 个，表格 M 个，图片 K 张，列表 L 组
  变更记录：已从 markdown 灌入 N 行                # 未提供时为「保留空表」
  警告：                                          # 有告警时
    - <图片缺失、层级降级等>
  目录域已通过 Word 更新 / 请打开文档后按 Ctrl+A、F9 更新
```

交付前人工检查：

1. 封面：文档名称、发布日期、保密等级正确，Q/DX 标志与标准号保持底稿原样
2. 目次：能看到各级标题与页码（目录为空时按 `Ctrl+A` → `F9`）
3. 标题：编号连续（`1`、`1.1`、`1.1.1`），无重复编号、无空标题
4. 表格：灰色表头、完整边框、跨页重复
5. 变更记录：位于末尾并另起一页，数据与 markdown 修订历史一致
6. 页眉：公司名与页码仍为底稿样式

转换完成后不要再用 Word 手工大改；需要调整内容时改 markdown 重新转换，避免两份内容分叉。

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 提示「底稿不满足模板契约」 | 传入的模板缺少必需样式或分节结构 | 使用 `assets/template.docx`；或用 `--check-template` 查看缺失项 |
| 封面仍是「文档名称」「2026 - 10 - 28发布」 | frontmatter 缺 `title` / `date` / `confidentiality` | 补齐 frontmatter 字段后重转 |
| 目录为空或显示占位文字 | 目录域未更新 | 打开文档按 `Ctrl+A` → `F9`；或确认本机 Word 可用 |
| 标题出现 `1 1. 概述` | 底稿标题样式未挂多级编号，脚本因此未剥离手工编号 | 使用自带底稿；或检查底稿标题样式的编号定义 |
| 变更记录列错位 | 表头语义未识别，已按列序兜底 | 把表头写成「版本 / 日期 / 修订人 / 修订内容」或「版本 / 变更日期 / 变更说明 / 记录人」 |
| 图片没显示 | 路径按相对 md 文件解析后不存在 | 修正路径，并查看摘要中的警告 |
| 代码块字体不是等宽 | 模板无代码样式，脚本用 `表格内文字` + Consolas | 如需统一字体，在底稿中新建代码样式并调整脚本契约 |
| 输出文件变成 `%TSD-Header` 密文 | 本机 DLP 对 Word 保存的文件透明加密 | 属预期，Word 可正常打开；但 python-docx 无法再读取该文件 |
| 中文乱码或提示无法识别编码 | md 既非 UTF-8 也非 GBK | 另存为 UTF-8 后重试 |
