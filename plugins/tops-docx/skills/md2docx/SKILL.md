# Markdown 转公司标准 Word 文档 (md2docx)

## 用途

读取一份 markdown 文件，以技能自带的 `assets/template.docx` 为**底稿（骨架 + 样式）**，生成符合青岛鼎信 Q/DX 技术文档标准的 Word 文档：

- 封面页、Q/DX 标志、标准号、发布部门、目次页、三节分页与页眉页脚 → 原样保留底稿
- 封面上的文档名称、发布日期、保密等级 → 用 frontmatter 填充
- 标题层级、段落、列表、表格、图片、代码块、变更记录 → 来自 markdown
- 底稿文件本身**不会被修改**，输出写入新文件

> 与通用「模板只提供样式」的转换不同：本技能的底稿自带封面与目次骨架，脚本只做「填空 + 注入正文」，不会重建封面，也不会清空分节结构。

## 触发条件

- 使用者说「转成 Word」「导出 docx」「生成 word 文档」时使用。
- 使用者已生成 markdown 文档并需要交付 Word 版本时使用。
- 使用者说 `/md2docx` 时使用。

## 前置条件

| 依赖 | 检查命令 | 缺失时的处理 |
|------|----------|--------------|
| Python 3.x | `python --version` | 提示使用者安装 Python |
| python-docx | `python -c "import docx; print(docx.__version__)"` | 打印 `pip install python-docx` 后停止，**不自动安装** |
| Word（可选） | 仅在更新目录页码时使用 | 不可用时转换照常完成，提示手动更新域 |

## 底稿与模板契约

默认底稿：`plugins/tops-docx/skills/md2docx/assets/template.docx`。转换前脚本会逐项校验契约；**不满足契约直接报错退出**，不会降级拼装。

### 底稿结构（脚本按分节符定位，三区缺一不可）

| 区域 | 内容 | 转换时的处理 |
|------|------|--------------|
| 第 1 节 | 封面（保密等级、Q/DX、标准号、文档名称、发布/实施日期、发布部门） | 保留，替换标题 / 发布日期 / 保密等级 |
| 第 2 节 | 目次页（「目　次」标题 + TOC 域，罗马页码） | 保留，清空缓存条目并重建 TOC 域 |
| 第 3 节 | 正文样例（「有序列表样式」示例、带序号列的样例表、末尾「变更记录」标准表，阿拉伯页码） | 先从样例读取列表缩进与表格列宽，再删除样例内容，追加 markdown 渲染结果与变更记录 |

### 必需样式

| 用途 | 样式名 |
|------|--------|
| 正文 | `段` |
| 一级标题 | `Heading 1` |
| 二级~六级标题 | `一级条标题`、`二级条标题`、`三级条标题`、`四级条标题`、`五级条标题` |
| 无序列表 1/2/3 层 | `列项——（一级）`、`列项●（二级）`、`列项◆（三级）` |
| 有序列表 | `段` + 底稿「有序列表样式」样例的编号定义（`1)`，样例段缩进 840/420） |
| 表格 / 单元格文字 | `Table Grid` / `表格内文字` |
| 图片 / 图题 | `图片格式` / `Caption` |
| 封面 | `封面标准名称`、`其他发布日期`、`文献分类号` |
| 目次 | `目次、标准名称标题`、`toc 1` |
| 变更记录标题 | `章标题` |
| 引用（可选） | `注：（正文）` |

## 调用方式

脚本位于本技能目录的 `scripts/md2docx.py`，用绝对路径调用：

```bash
python "<skill目录>/scripts/md2docx.py" --input "<markdown文件>" [--output "<输出docx>"]
```

Windows 示例：

```bash
python "E:\Github\pts-cluade-plugins\plugins\tops-docx\skills\md2docx\scripts\md2docx.py" ^
  --input "docs\电能表参数透传\PRD-电能表参数透传.md" ^
  --output "docs\电能表参数透传\PRD-电能表参数透传.docx"
```

### 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `--input` / `-i` | 是 | 输入 markdown 文件（建议 UTF-8） |
| `--output` / `-o` | 否 | 输出路径，默认与 markdown 同目录同名 `.docx` |
| `--template` / `-t` | 否 | 自定义底稿，默认使用技能自带的 `assets/template.docx`；底稿必须满足契约 |
| `--check-template` | 否 | 只校验底稿契约并输出逐项结果，不生成文档 |
| `--h1-pagebreak` | 否 | 每个一级标题前自动分页（默认关闭，仅变更记录固定另起一页） |
| `--skip-com` | 否 | 不调用 Word 更新目录域 |
| `--version` | 否 | 显示脚本版本 |

## markdown 约定

### frontmatter

文件顶部可带 YAML frontmatter（`tops-docx` 插件的四个文档技能默认会写入）：

```yaml
---
title: 电能表参数透传功能 产品需求文档
doc-type: PRD
version: V1.0
author: 张三
date: 2026-10-28
confidentiality: 内部
cover: true
toc: true
---
```

| 字段 | 作用 |
|------|------|
| `title` | 封面「文档名称」 |
| `date` | 封面发布日期，`2026-10-28` 会写成 `2026 - 10 - 28发布` |
| `confidentiality` | 封面保密等级（如 内部 / 限制 / 公开） |

未提供的字段保留底稿原文（`文档名称`、`2026 - 10 - 28发布`、`限制`）。`doc-type` / `version` / `author` 目前不上封面，可保留在 frontmatter 中。

### 标题

| markdown | 输出 |
|----------|------|
| 首个且唯一的一级标题 | 视为文档标题，只上封面，不进入正文 |
| `##` ~ `######` | 依次使用一级~五级条标题样式（标题层级整体上移一级） |
| 超过五级 | 降级为 `五级条标题` 并在摘要中提示 |

- 底稿标题样式自带多级编号（`1`、`1.1`、`1.1.1`），脚本会**自动剥离** markdown 标题中的手工编号（`1.`、`1.1`、`一、`、`第X章`），避免出现 `1 1. 概述`。
- 标题为 `目录` 或 `目次` 的章节整章跳过，目录由底稿目次页提供。

### 变更记录

标题为 `变更记录`、`修订记录`、`文档修订记录`、`修订历史`、`变更历史` 的章节：

- 该章节的表格数据行会灌入底稿末尾的标准表（版本 / 变更日期 / 变更说明 / 记录人）
- 表头按语义映射：`日期→变更日期`、`修订人→记录人`、`修订内容→变更说明`；识别不出时按列序兜底并在摘要提示
- 表格之外的内容忽略，并在摘要中告警
- markdown 没有该章节时，保留一张只有表头的空表
- 该章节固定置于全文末尾并另起一页，其余章节连续排版

### 支持的语法

| markdown | 输出 |
|----------|------|
| `#` ~ `######` | 见「标题」 |
| 普通段落 | `段`；中文换行自动拼接，不插空格 |
| `-` / `*` / `+`（支持 3 层嵌套） | `列项——（一级）` / `列项●（二级）` / `列项◆（三级）` |
| `1.` / `1)`（支持嵌套） | `段` + 底稿「有序列表样式」编号定义，显示 `1)` `2)` `3)`，每个列表独立从 1 开始，缩进取样例段自身的 `w:ind` |
| GFM 管道表格 | `Table Grid` + `表格内文字`，表头加粗、灰底、跨页重复；`:---:` 控制列对齐；首列为序号列时沿用底稿序号列宽（约 887 twips） |
| ```` ``` ```` | 逐行套 `表格内文字`，字体 Consolas |
| `>` | `注：（正文）`，自动补「注：」前缀 |
| `---` | 水平线（**不是**分页） |
| `\pagebreak` 或 `<!-- pagebreak -->` | 分页符 |
| `![图题](路径)` | `图片格式` 居中按版心宽缩放，图题用 `Caption` |
| `**粗体**` / `*斜体*` / `` `行内代码` `` / `[文字](链接)` | 行内格式；链接只保留可读文字 |
| HTML 注释、反斜杠转义 | 注释丢弃，`\_` 等转义按字面输出 |

### 表格列宽

- 首列识别为序号列时（表头是 `序号` / `编号` / `No.`，或表头为空且整列都是数字），列头统一写成「序号」，列宽取底稿样例表的序号列宽（约 887 twips）。
- 其余列按表头与单元格内容的显示长度分配宽度，表格总宽取底稿样例表总宽（9571 twips）。
- 其他列的表头保持 markdown 原文，不会替换成「列1」「列2」。
- 需要整体调整列宽时，修改底稿中带「序号」表头的样例表即可，脚本会重新读取。

### 不支持

- mermaid、PlantUML 等图形块：**原样保留为代码块**并告警，请改用文字、表格或本地图片
- 嵌套表格、脚注、公式、HTML 片段

## 输出与验收

脚本结束会打印：

```
[完成] 已生成：<输出路径>
  底稿：<底稿路径>
  文档标题：已作为封面标题处理，不写入正文
  统计：标题 N 个，表格 M 个，图片 K 张，列表 L 组
  变更记录：已从 markdown 灌入 N 行 / markdown 未提供，保留空表
  警告：
    - <图片缺失、层级降级等>
  目录域已通过 Word 更新 / 请打开文档后按 Ctrl+A、F9 更新
```

交付前人工检查：

1. 封面：文档名称、发布日期、保密等级正确，Q/DX 标志与标准号保持底稿原样
2. 目次：能看到各级标题与页码（目录为空时按 `Ctrl+A` → `F9`）
3. 标题：编号连续（`1`、`1.1`、`1.1.1`），无重复编号、无空标题
4. 表格：灰色表头、完整边框、跨页重复
5. 末尾变更记录另起一页，数据与 markdown 修订历史一致
6. 页眉公司名与页码仍为底稿样式

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 提示「底稿不满足模板契约」 | 传入的模板缺少必需样式或分节结构 | 使用 `assets/template.docx`；或运行 `--check-template` 查看缺失项 |
| 封面仍是「文档名称」「2026 - 10 - 28发布」 | frontmatter 缺 `title` / `date` / `confidentiality` | 补齐 frontmatter 字段后重转 |
| 目录为空或显示占位文字 | 目录域未更新 | 打开文档 `Ctrl+A` → `F9`；或确认本机 Word 可用 |
| 标题出现 `1 1. 概述` | 底稿标题样式未自动编号，脚本因此未剥离编号 | 检查底稿标题样式是否挂多级编号；或确认使用自带底稿 |
| 变更记录列错位 | 表头语义未识别，按列序兜底 | 把表头写成「版本 / 日期 / 修订人 / 修订内容」或「版本 / 变更日期 / 变更说明 / 记录人」 |
| 图片没显示 | 路径相对 md 文件解析且不存在 | 修正图片路径，查看摘要中的警告 |
| 代码块字体不是等宽 | 模板无代码样式，脚本用 `表格内文字` + Consolas | 如需统一字体，在底稿中新建代码样式并调整脚本契约 |
| 输出文件变成 `%TSD-Header` 密文 | 本机 DLP 对 Word 保存的文件透明加密 | 属预期，Word 可正常打开；但 python-docx 无法再读取该文件 |
| 中文乱码 | md 不是 UTF-8 | 另存为 UTF-8 后重试 |

## 注意事项

- **底稿只读**：脚本以底稿为母版加载后另存，不写回底稿；每次转换都从同一份底稿开始
- **不自动安装依赖**：缺少 Python 或 python-docx 时只提示，由使用者自行安装
- **不覆盖已有文件前先确认**：指定 `--output` 时若目标已存在，先向使用者确认再执行
- **转换后不要再用 Word 手工大改**：需要调整内容时改 markdown 再重新转换，避免两份内容分叉
- **封面标准号 / 实施日期 / 发布部门**保持底稿原文；如需按项目填写，先改底稿再转换
- 目录页码依赖 Word 域更新；脚本 best-effort 调用 Word COM，失败不影响文档生成，也不判定转换失败
