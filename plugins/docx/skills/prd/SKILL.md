# 产品需求文档 (prd)

## 用途

通过与使用者问答收集需求信息，按本文档定义的章节骨架产出**产品需求文档**，输出为 UTF-8 编码的 markdown 文件。

本技能只负责「写成 markdown」。需要 Word 文档时，由使用者再调用 `md2docx` 技能按 docx 模板转换。

## 触发条件

- 使用者要求「写产品需求文档」「写 PRD」「整理需求文档」时使用。
- 使用者给出一段需求描述并要求产出正式需求文档时使用。
- 使用者说 `/prd` 时使用。

## 输入来源

内容**只能来自问答**。成文前必须通过提问获得以下信息；使用者未提供的，逐个提问补齐，不得自行编造：

1. 项目或特性名称、文档用途、读者对象
2. 业务背景与要解决的问题
3. 目标用户/角色
4. 功能清单，以及每个功能的业务流程、规则、异常情况
5. 非功能要求（性能、兼容性、安全、可靠性）
6. 约束与依赖（外部系统、政策、硬件环境等）
7. 验收标准

提问方式：一次问一组相关问题，得到答复后再问下一组；使用者明确说「先按这个写」时，可在文档中标注待确认项。

## 工作流

1. 记录使用者给出的项目/特性名称，确认文档存放路径（见「输出」）。
2. 按「输入来源」逐组提问，边问边在脑中形成章节内容。
3. 按「章节骨架」逐章成文，章节顺序与编号保持不变。
4. 成文后自检：章节齐全、无跨文档引用、无未经确认的假设、术语前后一致。
5. 告知使用者将要写入的文件路径；目标文件已存在时先询问覆盖还是改名，确认后再写入。

## 输出

### 存放位置

```
docs/<项目或特性>/PRD-<名称>.md
```

### frontmatter

文件顶部必须包含以下字段（字段名固定，供 `md2docx` 识别封面信息）：

```yaml
---
title: <项目或特性名称> 产品需求文档
doc-type: PRD
version: V1.0
author: <作者>
date: <YYYY-MM-DD>
confidentiality: 内部
cover: true
toc: true
---
```

字段值未知时向使用者确认；确实无法确认时留空字符串，并在成文后列出待补充字段。

## 注意事项

- 文档内容**只能来自使用者答复**，不得编造业务规则、用户或指标
- **不得引用其他文档**：不出现「详见 HLD」「见详细设计」一类跨文档引用，PRD 必须能单独分发
- 未确认的内容必须显式标注为「待确认」，不要写成结论
- 表格**不要嵌套**，列表**不要嵌套**——`md2docx` 的解析器只支持单层结构
- 用例图、流程图等图形用文字或表格表达，不要使用 mermaid
- 文件必须为 UTF-8 编码
- 本技能不生成 docx；使用者需要 Word 版本时提示其调用 `md2docx` 技能
